自建 Miniflux 订阅 jdon.com，开「抓取原始内容」后全文永远是「点击验证你是真人」，点开原文也弹验证。根因是**缺少 Referer 触发人机验证**，恰好命中 Miniflux 的隐私设计。解法是加一层反代补上 Referer。

## 定位

文章页返回 200 但 body 是验证页，跳 `/captcha/refer.shtml`——路径里的 `refer` 就是提示。用 curl 做单变量矩阵：

| 请求方式 | 结果 |
| --- | --- |
| 任意 UA，无 Referer | 验证页 |
| 伪装 Chrome UA，无 Referer | 验证页（UA 是烟雾弹） |
| 任意 UA + 任意 Referer | 正常正文 |

两个易误判点：边缘缓存 `eo-cache-status: HIT` 直接回缓存不走校验，会偶发正常；伪装 Chrome 反而更容易中招（TLS 指纹与 UA 不一致是典型 bot 特征）。

## 为什么必中

- Miniflux 出于隐私设计，外链强制 `referrerpolicy="no-referrer"`，抓原文也不发 Referer
- 不支持按 feed 注入请求头（只有 UA / Cookie / 代理）
- HTTPS forward proxy 是隧道，**加不了 TLS 内的请求头**

## 绕过：nginx 反代补 Referer

```nginx
server {
    listen 8080;
    resolver 127.0.0.11 valid=600s ipv6=off;  # Docker 内嵌 DNS
    set $upstream https://www.jdon.com;

    # 只对 /rss 改写链接，让「抓原文」和「点开原文」都汇聚到本代理
    location = /rss {
        proxy_pass $upstream;
        proxy_set_header Host www.jdon.com;
        proxy_ssl_server_name on;
        proxy_set_header Referer https://www.jdon.com/;   # 核心
        proxy_set_header Accept-Encoding "";              # gzip 内容 sub_filter 改不了
        sub_filter 'https://www.jdon.com' 'https://rss-proxy.example.com';
        sub_filter_types application/rss+xml application/xml text/xml;
        sub_filter_once off;
    }

    # 其余路径纯透传（只补 Referer），HTML 不改写
    location / {
        proxy_pass $upstream;
        proxy_set_header Host www.jdon.com;
        proxy_ssl_server_name on;
        proxy_set_header Referer https://www.jdon.com/;
    }
}
```

Miniflux 把 feed URL 改指代理即可。

## 坑

- **`sub_filter_types` 是在 `text/html` 之外追加类型，不是替换**。想让 HTML 原样透传，必须把改写规则收进 `location = /rss`，别放公共 location
- **forward proxy ≠ 反代**：`proxy_url` / `HTTP_CLIENT_PROXY` 对 HTTPS 只能盲转 CONNECT，改请求头只能反代或 MITM
- 先在本机 Docker 起临时容器，curl 打真实上游验证改写与保真，再进 GitOps

## 一句话总结

反爬判据未必是 UA 或 IP，**Referer 这种「浏览器才有、客户端通常不伪造」的头**也是常见开关；排查用 curl 单变量矩阵最快，绕过最稳的是在链路上加一层能改头的反代。
