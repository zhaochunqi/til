自建 Miniflux 订阅极道（banq 的 jdon.com），开了「抓取原始内容」后，读到的全文永远是「点击验证你是真人」；点开原文也弹验证。排查下来既不是 IP 被封、也不是 User-Agent 被识别，而是一条 **Referer 缺失 → 人机验证** 的反爬规则，恰好命中 Miniflux 的隐私设计。

## 定位：一次只动一个变量

jdon.com 套着腾讯云 EdgeOne。首页和 `/rss` 怎么请求都正常，只有文章页（`/NNNN-*.html`）异常——返回 200 但 body 是验证页（`<title>验证</title>`，跳 `/captcha/refer.shtml`，路径名里的 `refer` 就是提示）。用 curl 做变量矩阵，立刻锁定判据：

| 请求方式 | 结果 |
| --- | --- |
| Miniflux UA / Chrome UA，无 Referer | 验证页 |
| curl 伪装 Chrome UA，无 Referer | 验证页（UA 伪装没用） |
| Miniflux UA + 任意 Referer | 正常正文 |
| 真实浏览器无 Referer 直访 | 验证页（复现点开原文的弹窗） |
| 真实浏览器带 Referer | 正常正文 |

两个容易误判的点：

- **边缘缓存会掩盖规则**：`eo-cache-status: HIT` 的响应直接回缓存、不走校验，所以偶发能打开，别被"有时正常"带偏。
- **UA 是烟雾弹**：伪装成 Chrome 反而更容易中招（TLS 指纹与 UA 不一致是典型 bot 特征），带 Referer 的 Miniflux UA 反而放行。

## 为什么 Miniflux 必中

- RSS 是摘要源（只有 ~150 字 description，无 `content:encoded`），读全文只能靠服务端抓原文或点跳转；
- Miniflux 出于隐私设计：外链强制 `rel="noopener noreferrer" referrerpolicy="no-referrer"`，爬虫抓原文也不发送 Referer；
- Miniflux 不支持按 feed 注入请求头（只有 User-Agent / Cookie / 代理），而 HTTPS forward proxy 是隧道，**加不了 TLS 内的请求头**。

三条路全堵死，所以是"必中"而非"偶发"。

## 绕过：反代注入 Referer

在 Miniflux 前面放一个 nginx 反代，统一补上站内 Referer：

```nginx
server {
    listen 8080;
    resolver 127.0.0.11 valid=600s ipv6=off;  # Docker 内嵌 DNS，上游换 IP 不用重启
    set $upstream https://www.jdon.com;

    # 只对 /rss 做链接改写，把条目链接改写到代理域名，
    # 让"抓原文"和"点开原文"都汇聚到本代理
    location = /rss {
        proxy_pass $upstream;
        proxy_set_header Host www.jdon.com;
        proxy_ssl_server_name on;
        proxy_set_header Referer https://www.jdon.com/;   # 核心：绕开人机验证
        proxy_set_header User-Agent "Mozilla/5.0 ... Chrome/154";
        proxy_set_header Accept-Encoding "";              # gzip 内容 sub_filter 改不了
        sub_filter 'https://www.jdon.com' 'https://rss-proxy.example.com';
        sub_filter_types application/rss+xml application/xml text/xml;
        sub_filter_once off;
    }

    # 其余路径纯透传（只补 Referer），正文 HTML 不改写
    location / {
        proxy_pass $upstream;
        proxy_set_header Host www.jdon.com;
        proxy_ssl_server_name on;
        proxy_set_header Referer https://www.jdon.com/;
        proxy_set_header User-Agent "Mozilla/5.0 ... Chrome/154";
    }
}
```

Miniflux 把 feed URL 改指代理即可，「抓取原始内容」照常开着。

## 踩到的坑

- **`sub_filter` 对 `text/html` 恒生效**：`sub_filter_types` 是在 text/html 之外**追加**类型，不是替换。想让 HTML 原样透传，就必须把改写规则收进 `location = /rss`，别放在公共 location 里。
- **forward proxy ≠ 反向代理**：Miniflux 的 per-feed `proxy_url`、全局 `HTTP_CLIENT_PROXY` 都是 forward proxy，对 HTTPS 只能盲转 CONNECT，无法注入 Referer；要改请求头只能反向代理或 MITM。
- **先本地验证再上线**：同一份 nginx.conf 在本机 Docker 起一个临时容器，curl 打真实上游，把"改写计数、验证码特征、HTML 是否保真"全部断言一遍，再 push 进 GitOps。

## 一句话总结

反爬规则的判定条件未必是 UA 或 IP，**Referer 这种"浏览器才有、客户端通常不伪造"的头**也是常见开关；排查时用 curl 做单变量矩阵最快，而绕过的最稳姿势是在自己的链路上加一层能改头的反向代理。
